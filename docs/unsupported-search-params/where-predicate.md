# Unsupported: `where(...)` predicates other than `field='value'` and `resolve() is Type`

The codegen handles two `where(...)` predicate shapes — `where(<field>='<string>')` and `where(resolve() is <Type>)`. Anything else inside the parentheses falls through to the unsupported stub. Across R4 / R4B / R5 core search params, only one parameter hits this gap: `QuestionnaireResponse.item-subject`, which uses an extension-presence check inside `where(...)`.

R4 spells this `hasExtension('<url>')`; R4B and R5 spell it `extension('<url>').exists()`. Both forms have the same intent: keep `item`s that carry the canonical `questionnaireresponse-isSubject` extension. Adding support would require parsing function-call predicates plus a way to look up extensions by canonical URL (see also [extension.md](extension.md)).

These same expressions also have an unsupported `.ofType(Reference)` post-`where(...)` tail (see also [of-type.md](of-type.md)). Either gap on its own is enough to make the parameter unsupported — fixing only one would not be sufficient.
